# CDID 数据分析平台 - 方案设计文档

**版本**: v0.2.0（基于 UI 确认）
**日期**: 2026-01-23
**目的**: 将 Gemini CLI 命令行流程包装成 Web 服务，降低使用门槛

---

## 1. 项目背景与目标

### 1.1 现状与痛点

**当前流程**（基于 Gemini CLI Skills）：
```
用户 → Gemini CLI → insight skill → analyzer skill → report skill → HTML 报告
```

**痛点**：
1. ❌ 必须懂命令行，技术门槛高
2. ❌ 需要手动配置 Gemini CLI（版本 >= v0.24.5，启用 skills）
3. ❌ 流程中有人工步骤（下载文件、本地分析）
4. ❌ 无法批量处理，无法追溯历史
5. ❌ 依赖 Go 二进制文件（analyzer），部署复杂

### 1.2 改造目标

**目标**：将命令行操作转化成 **Web 服务**，让任何人都能使用数据分析。

**新流程**：
```
用户浏览器 → Web UI → Python 后端 → 调用内网 API → 管线执行（Python分析 + Gemini Skill报告）→ 返回 Web UI
```

**核心价值**：
- ✅ **零门槛**：浏览器上传文件，选择客户即可
- ✅ **全自动**：后端自动调用 API、执行管线、生成报告
- ✅ **可追溯**：所有任务记录在数据库，可查询历史
- ✅ **可扩展**：方便添加新的管线（Python 脚本 + Gemini Skill）
- ✅ **纯 Python**：无需 Go 二进制，部署简单
- ✅ **客户管理**：支持客户-包名映射，简化任务创建

---

## 2. 核心概念变化：管线（Pipeline）

### 2.1 管线定义

**管线 = Python 数据处理脚本 + Gemini Skill（报告生成）**

一个管线包含：
1. **Python 脚本**：负责数据分析逻辑（多发/碰撞/风险检测等）
2. **Gemini Skill**：负责将分析结果生成 HTML 报告
3. **脚本目录**：Python 脚本所在的目录路径

### 2.2 管线工作流程

```
用户创建任务（选择管线）
   ↓
内网 API 获取数据（统一）
   ↓
管线执行：
   1. Python 脚本分析数据 → 输出 analysis_result.json
   2. Gemini Skill 生成报告 → 输出 report.html
   ↓
任务完成（用户可下载原始数据 + 报告）
```

### 2.3 任务执行策略

- **一个任务只执行一条管线**
- 如果管线失败，可以手动重新运行
- 管线失败后，Worker 自动处理下一个队列中的任务

## 4. 详细流程设计

### 4.1 用户创建任务流程

```
[用户] 选择客户（自动填充包名）+ 上传 CDID 文件 + 选择管线 + 时间范围
   ↓
[Web UI] POST /jobs (multipart/form-data)
   ↓
[API Server]
   1. 验证参数（客户名称、包名、管线、时间范围、数据类型）
   2. 保存上传文件到 jobs/{job_id}/input.csv
   3. 插入数据库 (status='queued')
   4. 返回 job_id
   ↓
[Worker] 从队列取任务 (status='queued')
   ↓
[阶段 1: Fetching] 调用内网 API 创建任务
   1. POST /api/statistical-analysis/v1/task/create
   2. 轮询查询状态 (建议每 60 秒，可配置)
   3. status='success' 后获取 oss_url
   4. 下载 Excel 到 jobs/{job_id}/raw_data.xlsx
   5. 更新数据库 (status='fetching', progress=XX%)
   ↓
[阶段 2: Analyzing] 执行管线 - Python 脚本
   1. 读取管线配置（脚本目录 + 脚本文件名）
   2. import 脚本并调用：analyze(input_file, user_info, start_date, end_date)
   3. 脚本返回分析结果 dict
   4. 保存为 jobs/{job_id}/analysis_result.json
   5. 更新数据库 (status='analyzing', progress=XX%)
   ↓
[阶段 3: Reporting] 执行管线 - Gemini Skill
   1. 读取管线配置（Skill 名称）
   2. 调用: cat analysis_result.json | gemini "@<skill_name> 根据以上JSON生成完整HTML报告，只输出HTML"
   3. 保存 HTML 到 jobs/{job_id}/report.html
   4. 更新数据库 (status='done', report_path='...')
   ↓
[用户] GET /jobs/{id}/report 查看报告
       GET /jobs/{id}/raw-data 下载原始数据
```

### 4.2 状态机设计

```
状态流转：queued → fetching → analyzing → reporting → done
         ↓ (任意阶段失败)
       failed
```

| 状态 | 说明 | 可重试 |
|------|------|--------|
| `queued` | 已创建，等待处理 | - |
| `fetching` | 调用内网 API，获取数据 | ✅ (网络错误可重试) |
| `analyzing` | Python 脚本执行数据分析 | ❌ (数据错误不可重试) |
| `reporting` | Gemini CLI 生成报告 | ✅ (LLM 可重试) |
| `done` | 完成 | - |
| `failed` | 失败（记录错误信息） | ✅ (用户可手动重新运行) |

### 5.3 Gemini CLI 调用（gemini_reporter.py）

**职责**：使用 Gemini CLI Headless Mode 调用指定 Skill

```python
class GeminiReporter:
    """Gemini CLI 报告生成器"""

    def generate_report(self, analysis_result: dict, skill_name: str) -> str:
        """
        生成 HTML 报告

        参数：
            analysis_result: 分析结果 dict
            skill_name: Gemini Skill 名称

        返回：
            HTML 字符串
        """
        # 将分析结果转为 JSON
        result_json = json.dumps(analysis_result, ensure_ascii=False, indent=2)

        # 调用 Gemini CLI（stdin 输入 + @skill_name 触发 Skill/扩展）
        prompt = f"@{skill_name} 根据以上JSON生成完整HTML报告，只输出HTML"
        cmd = ["gemini", prompt]

        process = subprocess.Popen(
            cmd,
            stdin=subprocess.PIPE,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            text=True
        )

        stdout, stderr = process.communicate(input=result_json)

        if process.returncode != 0:
            raise RuntimeError(f"Gemini CLI failed: {stderr}")

        return stdout  # HTML 报告
```

### 5.4 Worker 任务处理（worker.py）

**职责**：后台任务处理器（FIFO 队列，单线程）

```python
class Worker:
    """后台任务处理器"""

    async def process_job(self, job):
        """处理单个任务"""
        # 阶段 1: Fetching
        self.update_status(job.id, 'fetching', progress=10)
        task_id = await self.insight_client.create_task(...)

        # 轮询等待
        result = await self.wait_for_task_completion(task_id)

        # 下载数据
        await self.insight_client.download_result(
            result['oss_url'],
            f'jobs/{job.id}/raw_data.xlsx'
        )

        # 阶段 2: Analyzing - 执行 Python 脚本
        self.update_status(job.id, 'analyzing', progress=50)

        # 获取管线配置
        pipeline = self.get_pipeline_config(job.pipeline_id)

        # 动态导入 Python 脚本
        script_module = self.load_script(pipeline.script_dir, pipeline.script_file)

        # 调用标准接口
        analysis_result = script_module.analyze(
            input_file=f'jobs/{job.id}/raw_data.xlsx',
            user_info={'user_id': job.user_id, 'task_id': job.id},
            start_date=job.start_date,
            end_date=job.end_date
        )

        # 保存分析结果
        with open(f'jobs/{job.id}/analysis_result.json', 'w') as f:
            json.dump(analysis_result, f, ensure_ascii=False, indent=2)

        # 阶段 3: Reporting - 调用 Gemini Skill
        self.update_status(job.id, 'reporting', progress=80)

        html_report = self.reporter.generate_report(
            analysis_result,
            skill_name=pipeline.skill_name
        )

        # 保存报告
        with open(f'jobs/{job.id}/report.html', 'w') as f:
            f.write(html_report)

        # 完成
        self.update_status(job.id, 'done', progress=100)
```

## 10. 关键技术点

### 10.1 Python 脚本动态加载

```python
import importlib.util

def load_script(script_dir: str, script_file: str):
    """动态加载 Python 脚本模块"""
    script_path = os.path.join(script_dir, script_file)

    spec = importlib.util.spec_from_file_location("script_module", script_path)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)

    return module
```

### 10.2 Gemini Skill 导入（非新建）

**Skill/扩展配置原则（MVP）**：
1. Skill/扩展由管理员在 Gemini CLI 环境中**预先安装/配置**（平台不负责复制/安装）
2. 平台仅保存并引用 `skill_name`（用于 prompt 里的 `@<skill_name>`）
3. 如新增/更新 Skill/扩展后需要生效，按现网要求手动重启 Gemini CLI

**注意**：
- ❌ 不支持在 Web UI 中新建 Skill/扩展（目录结构/权限/运维流程复杂）
- ✅ 管线配置只关心 “调用哪个 @skill_name”
- ✅ 如需校验可用列表，可参考 Gemini CLI 的扩展/能力列举命令（以现网 CLI 为准）

### 10.3 客户-包名自动填充

**前端实现**：
```javascript
const clientPackageMap = {
    '示例客户A': 'com.example.clienta',
    '示例客户B': 'com.example.clientb',
    // 从后端 API 获取
};

clientNameInput.addEventListener('input', function() {
    const clientName = this.value.trim();
    if (clientPackageMap[clientName]) {
        packageNameInput.value = clientPackageMap[clientName];
    }
});
```

**后端 API**：
