## 1. 项目背景与目标

### 1.1 现状与痛点

**当前流程**（基于 Gemini CLI Skills）：
```
用户 → Gemini CLI → insight skill → analyzer skill → report skill → HTML 报告
```

**痛点**：
1. ❌ 必须懂命令行，技术门槛高
2. ❌ 需要手动配置 Gemini CLI
3. ❌ 流程中有人工步骤
4. ❌ 无法批量处理，无法追溯历史

### 1.2 改造目标

**新流程**：
```
用户浏览器 → Web UI → Python 后端 → 调用内网 API → Python 统计分析 → Gemini CLI + Skill → 返回 Web UI
```

**核心价值**：
- ✅ **零门槛**：浏览器上传文件即可
- ✅ **全自动**：后端自动化处理
- ✅ **可追溯**：所有任务记录数据库
- ✅ **智能报告**：利用 Gemini CLI + Skill 生成个性化报告

## 3. 详细流程设计（更新）

### 3.1 完整数据流

```
[用户] 上传 CDID 文件 (波克问题数据.csv)
   ↓
[API Server] 保存到 jobs/{job_id}/input.csv
   ↓
[Worker]
   │
   ├─ [阶段 1: Fetching] 调用内网 API
   │   1. POST 创建任务 (需要 start/end 参数 YYYY-MM-DD)
   │   2. 轮询查询状态 (每 30 秒)
   │   3. 下载 Excel → jobs/{job_id}/raw_data.xlsx
   │      字段：cdid, did, oaid, imei, android_id, rc_rules, rc_scenes
   │
   ├─ [阶段 2: Analyzing] Python 统计分析
   │   1. 读取 raw_data.xlsx
   │   2. 统计 unique_did_count = df['did'].nunique()
   │   3. 统计 unique_oaid_count = df['oaid'].nunique()
   │   4. 计算 ratio = unique_did_count / unique_oaid_count
   │   5. 判定 is_duofa = (ratio > 2)
   │   6. 构建数据包 (含处理过程、统计结果、背景知识)
   │   7. 保存 → jobs/{job_id}/analysis_result.json
   │
   └─ [阶段 3: Reporting] Gemini CLI 生成报告
       1. 读取 analysis_result.json
       2. 调用: cat analysis_result.json | gemini -p "使用 duofa-panduan skill 生成报告"
       3. Gemini CLI 加载 ~/.gemini/skills/duofa-panduan/SKILL.md
       4. Skill 提供多发背景知识
       5. Gemini 根据 Skill + 数据生成 HTML 报告
       6. 保存 → jobs/{job_id}/report.html
   ↓
[用户] GET /jobs/{id}/report 查看报告
```

### 3.2 状态机设计

```
状态流转：queued → fetching → analyzing → reporting → done
         ↓ (任意阶段失败)
       failed
```

**职责**：**只做多发检测统计**（简化！）

import pandas as pd
from typing import Dict, Any

class DuofaAnalyzer:
    """多发检测分析器（简化版）"""

    def analyze(self, input_file: str, job_info: dict) -> Dict[str, Any]:
        """
        分析数据

        输入: raw_data.xlsx（内网 API 下载的文件）
        输出: 数据包（含处理过程、统计结果、背景知识）

        # 1. 读取数据
        df = pd.read_excel(input_file)

# 多发检测报告生成

## 背景知识

### 什么是多发？

**多发**（Duofa）是指多个设备标识（did）共享少量的广告标识（oaid），这通常表明存在以下问题：

1. **设备伪造**：使用虚拟设备或模拟器批量生成设备 ID
2. **刷量作弊**：通过脚本自动化操作，伪造大量用户行为
3. **设备农场**：使用大量真实设备进行自动化操作

### 判定逻辑

**核心公式**：
```
ratio = unique_did_count / unique_oaid_count
```

**判定规则**：
- ratio > 2.0 → **多发异常**（红色标记）
- ratio ≤ 2.0 → **正常范围**（绿色标记）

**业务含义**：
- ratio = 1.0：理想情况，一个 did 对应一个 oaid
- ratio = 2.0：临界值，可能存在少量共享
- ratio > 2.0：异常，大量 did 共享少量 oaid，高度怀疑作弊

### 数据字段说明

- **did**：设备标识（Device ID），唯一标识一台设备
- **oaid**：开放匿名设备标识符（Open Anonymous Device Identifier），用于广告投放的匿名标识
- **unique_did_count**：去重后的 did 数量（有多少台不同的设备）
- **unique_oaid_count**：去重后的 oaid 数量（有多少个不同的广告标识）
- **ratio**：did/oaid 比例（平均每个 oaid 对应多少个 did）

### 风险等级

| ratio 范围 | 风险等级 | 说明 |
|-----------|---------|------|
| ≤ 1.5 | 低风险 | 正常设备行为 |
| 1.5 - 2.0 | 中风险 | 需要关注 |
| 2.0 - 5.0 | 高风险 | 疑似作弊 |
| > 5.0 | 极高风险 | 严重作弊 |

## 任务

根据用户输入的统计数据和计算结果，生成一份**专业的多发检测报告**。

### 报告要求

**格式**：HTML（包含完整的 `<html>`, `<head>`, `<body>` 标签）

**必须包含的章节**：

1. **执行摘要**
   - 任务基本信息（任务名称、包名、时间范围）
   - 核心结论（是否多发、风险等级）
   - 关键数据（did 数量、oaid 数量、比例）

2. **数据统计**
   - 总行数
   - unique_did_count
   - unique_oaid_count
   - ratio（高亮显示）
   - 判定结果（使用颜色标记）

3. **风险分析**
   - 根据 ratio 判断风险等级
   - 解释为什么这个比例表明多发
   - 可能的业务影响

4. **数据样例**
   - 展示前 5 条原始数据（以表格形式）
   - 说明数据字段含义

5. **建议与结论**
   - 如果是多发：建议采取的措施（如屏蔽、人工审核）
   - 如果正常：说明数据质量良好
   - 后续监控建议

### 样式要求

- 使用 **Bootstrap 5 CDN**（或内联 CSS）
- 多发结果用**红色**标记（bg-danger, text-danger）
- 正常结果用**绿色**标记（bg-success, text-success）

### 4.4 Gemini CLI 调用（gemini_reporter.py）

```python
import subprocess
import json
from pathlib import Path
from typing import Dict, Any

class GeminiReporter:
    """Gemini CLI 报告生成器"""

    def __init__(self, config):
        self.gemini_cli_path = config.gemini_cli_path  # 可配置路径
        self.skill_name = "duofa-panduan"

    def generate_report(self, analysis_result: Dict[str, Any]) -> str:
        """
        使用 Gemini CLI + Skill 生成 HTML 报告

        输入: 数据包（dict）
        输出: HTML 字符串
        """
        # 1. 转换为 JSON
        result_json = json.dumps(analysis_result, ensure_ascii=False, indent=2)

        # 2. 构建 prompt
        prompt = f"使用 {self.skill_name} skill 根据以下数据生成多发检测报告"

        # 3. 调用 Gemini CLI（管道输入）
        cmd = [
            self.gemini_cli_path,  # 例如：/usr/local/bin/gemini 或 gemini
            "-p", prompt
        ]

        process = subprocess.Popen(
            cmd,
            stdin=subprocess.PIPE,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            text=True
        )

        stdout, stderr = process.communicate(input=result_json)

        # 4. 错误处理
        if process.returncode != 0:
            raise RuntimeError(f"Gemini CLI 调用失败: {stderr}")

        # 5. 返回 HTML
        return stdout
```

**关键变化**：
- ✅ 支持可配置的 Gemini CLI 路径
- ✅ Prompt 中明确引用 Skill 名称
- ✅ 通过管道传入完整的数据包

### 4.5 Worker 任务处理（worker.py）

**无重大变化**，参考 v1.0，但简化了 analyzing 阶段：

```python
async def process_job(self, job):
    """处理单个任务"""

    # 阶段 1: Fetching
    self.update_status(job.id, 'fetching', progress=10)
    task_id = await self.insight_client.create_task(
        name=job.name,
        package_name=job.package_name,
        file_path=f'jobs/{job.id}/input.csv',
        start_date=job.start_date,  # 必填
        end_date=job.end_date,      # 必填
        message_types=job.message_types
    )

    # 轮询等待
    while True:
        status = await self.insight_client.query_task_status(task_id)
        if status['status'] == 'success':
            break
        await asyncio.sleep(30)  # 每 30 秒轮询一次

    # 下载数据
    await self.insight_client.download_result(
        status['oss_url'],
        f'jobs/{job.id}/raw_data.xlsx'
    )

    # 阶段 2: Analyzing（简化！）
    self.update_status(job.id, 'analyzing', progress=50)
    analysis_result = self.analyzer.analyze(
        f'jobs/{job.id}/raw_data.xlsx',
        job_info={
            "name": job.name,
            "package_name": job.package_name,
            "start_date": job.start_date,
            "end_date": job.end_date
        }
    )

    # 保存分析结果
    with open(f'jobs/{job.id}/analysis_result.json', 'w') as f:
        json.dump(analysis_result, f, ensure_ascii=False, indent=2)

    # 阶段 3: Reporting
    self.update_status(job.id, 'reporting', progress=80)
    html_report = self.reporter.generate_report(analysis_result)

    # 保存报告
    with open(f'jobs/{job.id}/report.html', 'w') as f:
        f.write(html_report)

    # 完成
    self.update_status(job.id, 'done', progress=100, report_path=f'jobs/{job.id}/report.html')
```

## 12. 关键技术点（更新）

### 12.1 Gemini CLI + Skill 调用

**命令行等效**：
```bash
cat analysis_result.json | gemini -p "使用 duofa-panduan skill 根据以下数据生成多发检测报告"
```

**Gemini CLI 行为**：
1. 读取 stdin（JSON 数据包）
2. 解析 prompt，识别到 "duofa-panduan skill"
3. 加载 `~/.gemini/skills/duofa-panduan/SKILL.md`
4. 结合 Skill 内容 + 数据包生成报告
5. 输出 HTML 到 stdout

### 12.2 Skill 的作用

**Skill 不是简单的 prompt 模板**，而是：
- ✅ 提供**领域知识**（什么是多发？为什么重要？）
- ✅ 定义**判定规则**（ratio > 2）
- ✅ 指导**报告结构**（必须包含哪些章节）
- ✅ 规范**样式要求**（Bootstrap、颜色语义）

**Gemini CLI 的优势**：
- Skill 可以随时更新，无需改代码
- Gemini 会根据 Skill + 数据智能生成报告（不是固定模板）
- 报告个性化、自然语言生成
