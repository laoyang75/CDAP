### 任务 3：Python 分析脚本模板和执行器

**目标**：创建标准化的分析脚本接口和动态加载机制

**创建文件**：
- `src/scripts/duplicate_detection/analyzer.py` - 多发检测分析脚本
- `src/worker/pipeline_executor.py` - 管线执行器（动态加载脚本）
- `tests/test_pipeline_executor.py` - 单元测试

**标准分析接口**：
```python
def analyze(input_file: str, user_info: dict, start_date: str, end_date: str) -> dict:
    """
    所有分析脚本必须实现此接口

    参数：
        input_file: 原始数据文件路径（Excel）
        user_info: 用户信息 {'user_id': '...', 'task_id': '...'}
        start_date: 开始日期 (YYYY-MM-DD)
        end_date: 结束日期 (YYYY-MM-DD)

    返回：
        dict: 分析结果（必须可 JSON 序列化）
    """
```

**分析逻辑（MVP）**：
1. **多发检测**：相同设备标识（did/oaid/android_id/imei）关联多个 CDID
2. **碰撞检测**：相同 DID 出现不同设备型号
3. **风险检测**：rc_rules 或 rc_scenes 非空（MVP 兜底逻辑）

**输出格式**：
```json
{
  "job_id": "01J...",
  "analyzed_at": "2026-01-23T18:00:00Z",
  "summary": {
    "total_cdid": 100,
    "duplicate_count": 15,
    "impact_count": 8,
    "risk_count": 3
  },
  "duplicate": [...],
  "impact": [...],
  "risk": [...]
}
```

**关键技术**：
- Pandas（数据处理）
- importlib（动态模块加载）
- 字段映射（处理不同列名）

### 任务 4：Gemini CLI 报告生成器集成

**目标**：通过 Gemini CLI 生成 HTML 报告

**创建文件**：
- `src/worker/gemini_reporter.py` - Gemini CLI 调用封装
- `tests/test_gemini_reporter.py` - 单元测试

**调用方式**：
```bash
cat analysis_result.json | gemini "@<skill_name> 根据以上JSON生成完整HTML报告，只输出HTML代码"
```

**工作流程**：
1. 将分析结果序列化为 JSON
2. 通过 stdin 管道传入 Gemini CLI
3. 在 prompt 中使用 `@skill_name` 触发指定 Skill
4. 从 stdout 获取 HTML 报告
5. 保存到 `jobs/{job_id}/report.html`

**错误处理**：
- 超时控制（默认 5 分钟）
- stderr 日志记录
- 进程退出码检查

**关键技术**：
- subprocess（子进程管理）
- stdin/stdout 管道
- 超时处理

### 任务 5：Worker 主循环实现

**目标**：后台任务处理器，实现完整的任务生命周期

**创建文件**：
- `src/worker/main.py` - Worker 主程序
- `tests/test_worker_main.py` - 单元测试

**任务处理流程**（4 个阶段）：

**阶段 1：Fetching（获取数据）**
- 调用内网 API 创建任务
- 轮询查询状态（建议 60 秒间隔）
- 下载结果到 `jobs/{job_id}/raw_data.xlsx`
- 更新进度：10% → 45%

**阶段 2：Analyzing（数据分析）**
- 动态加载管线配置的 Python 脚本
- 调用 `analyze()` 函数
- 保存结果到 `jobs/{job_id}/analysis_result.json`
- 更新进度：50% → 70%

**阶段 3：Reporting（生成报告）**
- 调用 Gemini CLI 生成 HTML
- 保存报告到 `jobs/{job_id}/report.html`
- 更新进度：80% → 95%

**阶段 4：Done/Failed（完成或失败）**
- 更新最终状态
- 记录错误信息（如果失败）
- 进度：100%

**Worker 主循环**：
- FIFO 队列（先进先出）
- 单线程处理（MVP）
- 轮询间隔：5 秒
- 自动处理失败任务的下一个任务

**关键技术**：
- asyncio（异步编程）
- 状态机管理
- 错误恢复机制

### 任务 6：FastAPI 服务器 - 核心端点

**目标**：实现任务管理的 REST API

**创建文件**：
- `src/api/main.py` - FastAPI 应用入口
- `src/api/routes/jobs.py` - 任务相关路由
- `src/api/dependencies.py` - 依赖注入
- `tests/test_api_jobs.py` - API 测试

**API 端点**：

1. **POST /jobs** - 创建任务
   - 文件上传（multipart/form-data）
   - 参数：name, client_name, package_name, pipeline_id, start_date, end_date, message_types
   - 返回：job_id, status, created_at

2. **GET /jobs** - 任务列表
   - 支持筛选：status, user_id
   - 按创建时间倒序排列

3. **GET /jobs/{id}** - 任务详情
   - 返回完整任务信息（包括进度、错误信息）

4. **GET /jobs/{id}/report** - 获取 HTML 报告
   - 返回 HTML 文件

5. **GET /jobs/{id}/raw-data** - 下载原始数据
   - 返回 Excel 文件

6. **POST /jobs/{id}/retry** - 重新运行失败任务
   - 将状态重置为 queued

7. **DELETE /jobs/{id}** - 删除任务
   - 软删除（设置状态为 deleted）

**关键技术**：
- FastAPI（现代 Web 框架）
- 文件上传处理
- FileResponse（文件下载）
- CORS 中间件
