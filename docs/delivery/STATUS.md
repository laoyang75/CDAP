# delivery 目录状态说明

## 结论
`delivery/` 已不再作为日常开发主目录，建议视为**历史线下交付快照**。

## 判断依据
- 当前 Git 化开发的主代码目录是 `cdid-analysis-platform/`。
- `delivery/cdid-analysis-platform/` 文件集合是主目录的子集，主要用于过去线下交付。
- 持续在两个目录同步修改会带来重复维护和遗漏风险。

## 当前策略（已执行）
- 主开发与代码审查统一使用：`cdid-analysis-platform/`
- `delivery/` 暂时保留为历史兼容目录，不再作为功能演进来源。
- 交付相关文档统一收敛到：`docs/delivery/`

## 后续建议
1. 若未来不再需要线下打包交付，可删除 `delivery/` 目录。
2. 若仍需要一次性离线交付，建议由主目录自动打包生成发布产物，而不是维护双份代码。
